<Update label="October 11, 2026" description="Release Notes for Build 5.103.4.725">

This release adds attribute-based layer filtering to the Geo Map and significantly improves the connection handling, polling, and diagnostics of the AVEVA PI Interface Proxy. Several fixes improve proxy reliability, caching, and error reporting.

### New Features

- **Geo Map - Layer Filters:**  
  Geo map layers can be filtered by attribute values from the Layers panel. Filters support AND conditions, run on the ESRI ArcGIS server, and update the legend to show only matching feature classes.

- **Geo Map - Filter Operators:**  
  Added ESRI ArcGIS Map Viewer filter operators, including text operators, blank values, and numeric ranges. Attribute values can be selected from lists that show counts and coded-value names.

- **Geo Map - Filters in Links:**  
  Layer filters are preserved in page links and carried into dashboards opened from the map.

- **AVEVA PI Interface Proxy - Connection Handling:**  
  Improved connection handling with pooled PI connections, individual read timeouts, and a dedicated data pipe connection, so slow or failed reads no longer block other operations.

- **AVEVA PI Interface Proxy - Follow Backfilled Values:**  
  Added Follow Backfilled Values (disabled by default) to detect backfilled updates or deletions that affect the current PI snapshot.

- **AVEVA PI Interface Proxy - Background Polling:**  
  Added background polling for unavailable points and failed subscriptions, with automatic restoration to data pipe subscriptions when they become available.

- **AVEVA PI Interface Proxy - Diagnostics Endpoint:**  
  Added the `getproxymetrics` endpoint for subscription and polling diagnostics.

- **Server Manager - AVEVA PI Interface Proxy Settings:**  
  Added AVEVA PI Interface Proxy settings for polling interval, connection pool size, request timeout, cache expiration, advanced connection options, and polling diagnostics.

- **AVEVA PI RDA Interface - Interface Proxy Timeout:**  
  Added a configurable Interface Proxy Timeout (default 600 seconds) to support large data requests, with improved timeout logging and error messages.

### Fixes

- **AVEVA PI Interface Proxy / Server Manager:**  
  Reduced the data pipe collection interval from 30 seconds to 1 second to prevent event queue overflows and dropped updates. Upgrades now correct the old default while preserving custom settings.

- **AVEVA PI Interface Proxy:**  
  HTTP error responses now return appropriate status codes (400, 503, 504, 500) instead of HTTP 200 with an empty response.

- **AVEVA PI Interface Proxy:**  
  Improved value caching to expire unused entries, remove obsolete subscriptions, prevent stale values from recreated points, and eliminate empty values during cache expiration.

- **AVEVA PI Interface Proxy:**  
  Improved connection recovery and service reliability, including safe reconnection, automatic restart on persistent failures, Windows service recovery, exception logging, and startup port validation.

- **AVEVA PI Interface Proxy:**  
  Eliminated repeated temporary AF known-server entries. PI-only servers now maintain a single persistent TransparaPIProxy entry.

- **AVEVA PI Interface Proxy:**  
  Improved startup configuration logging to distinguish informational notices from invalid configuration warnings.

- **Virtual Dashboards:**  
  Fixed missing background colors on AF event-frame generic and dashboard link blocks without an assigned color.

- **Geo Map:**  
  Improved layer filter error handling, attribute value list retries, numeric input validation, and editing stability. Removed unnecessary "(no features)" labels and fixed Layers panel resizing.

**Compatibility:**  
Tested with inmation version v1.94.3.21651.

</Update>

<Update label="September 18, 2026" description="Release Notes for Build 5.103.1.722">

This release adds ESRI ArcGIS Feature Server layers to the KPI geo map, including secured layers, along with new Designer and Server Manager settings. It also adds Follow Backfilled Values to the AVEVA AF Interface Proxy and improves tModel RCS and AspenTech inmation Interface behavior.

**Note:** This release includes a schema change. Upgrade your Visual KPI Designer(s).

### New Features

- **Geo Map - ESRI ArcGIS Layers:**  
  ESRI ArcGIS Feature Server layers can now be drawn on the KPI geo map, with a Layers control to toggle each layer and set its opacity.

- **Geo Map - Layer Groups:**  
  A layer URL that points at a Feature Server root is drawn as a group of layers, with one child row per service layer. The group's checkbox and opacity apply to all its children, and the children's state rolls back up to the group row.

- **Geo Map - Feature Popups:**  
  Clicking the map opens a popup, laid out like the ESRI ArcGIS Online default popup, that pages through every feature under the click. The feature being shown is outlined on the map: a clicked point is highlighted in the shape of its own marker, and a line in its own dash pattern.

- **Geo Map - Secured ESRI ArcGIS Layers:**  
  For secured layers, the layer's username and password are used server-side to fetch and cache an ArcGIS token, so neither the credentials nor the token ever reach the browser.

- **Designer - Layers Sheet:**  
  Added a Layers sheet under Advanced to define ESRI ArcGIS layers, and a Geo Layer(s) column on the Group sheet to assign one or more layers to a group.

- **Designer - Secured Layer Credentials:**  
  Username and write-only Password columns on the Layers sheet mark a layer as secured. The password is encrypted on save and never read back.

- **Server Manager - tModel Group Picker:**  
  Added a group picker for the tModel RCS root group and the tModel interface start group.

- **Server Manager - Follow Backfilled Values:**  
  Added the "Follow Backfilled Values" setting for the AVEVA AF Interface Proxy.

- **Server Manager - AVEVA AF Proxy Connection Pool Size:**  
  The AVEVA AF Proxy connection pool size is now a settings field (default 8; 0 uses a temporary connection per request) instead of a manual edit of the proxy config file.

- **Server Manager - Install Paths:**  
  Windows services now show their install path, and the "…" button opens the folder in Windows Explorer. The same applies to the interface and instance paths.

- **AVEVA AF Interface Proxy - Follow Backfilled Values:**  
  When "Follow Backfilled Values" is enabled (off by default), a subscription event older than the cached value, or a delete, makes the proxy re-read that attribute's current value. A backfill that rewrites or deletes the PI snapshot with an earlier timestamp is then picked up instead of being ignored until the cache entry expires.

- **Transpara tModel RCS - Status Override:**  
  A KPI with a populated Transpara tModel Status Override always binds its status to the Transpara tModel status, regardless of the Overwrite Status setting.

- **Transpara tModel RCS - tGraph Lookups:**  
  Lookups that resolve inside Transpara tGraph are also served through the Transpara tStore interface.

- **AspenTech inmation Interface - Aggregation Interval:**  
  Lookups accept an aggregation interval, which current value, historical value, trends, and historical ranges honor.

### Fixes

- **Server Manager:**  
  Fixed the default tGraph Base URL for the tModel RCS and the tModel interface.

- **Geo Map:**  
  Polygon and line layers are loaded per tile for the current zoom level, and failed feature queries are retried, so large layers draw progressively instead of timing out.

- **Geo Map:**  
  The map's auto-fit now covers only the KPIs. Drawing or toggling a layer no longer moves or widens the viewport.

- **Geo Map:**  
  Layer URLs are now validated, so only Feature Server layers and service roots are accepted. A layer that fails to load keeps its controls and reports the error instead of disappearing.

- **Transpara tModel RCS:**  
  A KPI whose tModel has no status lookup still binds its status to the Status Override.

- **AVEVA AF Interface Proxy:**  
  Attributes with a broken AVEVA PI Point reference (point not found or referenced attribute missing) are now polled in the background and promoted back to the data pipe once they resolve, instead of being evicted and re-read cold on every Visual KPI refresh.

- **AVEVA AF Interface Proxy:**  
  Startup configuration notices are now logged at the right level. Valid but inconsistent settings are logged as Information, naming the exact key and value to set, and defaulted invalid values are logged as warnings, rather than appearing as errors on every start.

**Compatibility:**  
Tested with inmation version v1.94.3.21651.

</Update>

<Update label="September 2, 2026" description="Release Notes for Build 5.102.40.715">

This release improves how the AVEVA AF Interface and AVEVA AF Interface Proxy handle long-running and high-volume reads, with new timeout and concurrency settings exposed in Server Manager.

### New Features

- **AVEVA AF Interface - Interface Proxy Timeout:**  
  Added a configurable Interface Proxy Timeout setting for long-running proxy requests, with a default of 600 seconds.

- **AVEVA AF Interface Proxy - Read Hang Timeout:**  
  Added a separate Read Hang Timeout setting so healthy long-running bulk reads are not treated as hung requests.

- **AVEVA AF Interface Proxy - Request Timeout Default:**  
  Increased the default Request Timeout from 300 to 600 seconds.

- **AVEVA AF Interface Proxy - Slow-Read Logging:**  
  Slow-read logging now includes the number of distinct AVEVA PI Data Archives accessed by each batch.

- **AVEVA AF Interface Proxy - Max Concurrent Reads:**  
  Added an optional Max Concurrent Reads setting for sites where PI Data Archive read concurrency needs to be limited.

- **Server Manager - Interface Proxy Timeout:**  
  Added Interface Proxy Timeout configuration under the AVEVA AF Interface proxy settings.

- **Server Manager - AVEVA AF Interface Proxy Settings:**  
  Added Request Timeout, Read Hang Timeout, Subscription Batch Size, and Max Concurrent Reads settings for the AVEVA AF Interface Proxy.

### Fixes

- **AVEVA AF Interface:**  
  Proxy timeouts now clearly report the configured timeout value and cancellation status.

- **AVEVA AF Interface:**  
  Verify Connection now reports proxy timeout errors correctly instead of failing with a null reference.

- **AVEVA AF Interface:**  
  Proxy communications now use a shared HTTP client for more reliable connection and timeout handling.

- **AVEVA AF Interface Proxy:**  
  Long-running reads can now complete and populate the cache even after the original request times out.

- **AVEVA AF Interface Proxy:**  
  Multiple requests for the same values now share an active read instead of starting duplicate reads.

- **AVEVA AF Interface Proxy:**  
  Improved subscription processing at scale by batching and pacing data pipe signups, polling, and resynchronization activity.

- **AVEVA AF Interface Proxy:**  
  Attributes that cannot be served by the AVEVA PI data pipe, including time-range and summary calculations, are now polled instead of being re-read from AF on every refresh.

- **Server Manager:**  
  The AVEVA AF Proxy Observable Events Collection Interval now defaults to 1 second to match the proxy default.

**Compatibility:**  
Tested with inmation version v1.94.3.21651.

<Update label="September 1, 2026" description="Release Notes for Build 5.102.37.712">

This release significantly improves the scalability and reliability of tModel RCS and the AVEVA AF Proxy. tModel RCS gains page-by-page processing, compressed responses, and reworked logging, while the AVEVA AF Proxy gains a warm connection pool and faster large current-value reads. Several data and stability issues have also been fixed.

### New Features

- **tModel RCS - Page-by-Page Processing:**  
  Models are now processed page by page, so very large models no longer run out of memory.

- **tModel RCS - Gzip Compression:**  
  Get-by-property responses are now Gzip-compressed, producing payloads roughly 11x smaller against tgraph-api 1.61 and later. A `GzipResponses` setting is available as an escape hatch.

- **tModel RCS - tStore Interface Routing:**  
  tStore-backed attributes are routed to a separate Visual KPI tStore interface, detected automatically from tgraph.

- **tModel RCS - Custom Attributes for Charts:**  
  Custom attributes are now written for pie, bar, Pareto, box plot, and trend objects.

- **tModel RCS - Logging Rework:**  
  Full-level logging now shows per-page and per-type summaries instead of per-object SDK noise, plus one line per HTTP request with method, URL, status, round-trip time, and response size.

- **tModel RCS - Retries and Token Caching:**  
  Dropped requests are retried with backoff, and bearer tokens are cached instead of re-authenticating each time. Batches that still fail now fail the cache run instead of saving an incomplete data set as successful.

- **Server Manager - tModel RCS Settings:**  
  tModel RCS settings now include Get By Property Batch Size, Parallel Requests, separate tModel and tStore interface pickers, and Always Use tModel Interface.

- **AVEVA AF Proxy - Warm Connection Pool:**  
  Reads now use a warm connection pool, so concurrent requests no longer share a single AF SDK connection. This resolves random service deaths and race condition errors under load.

- **AVEVA AF Proxy - Connection Pool Size:**  
  Added the `af_connection_pool_size` setting, with a default of 8. Set it to 0 to revert to the previous single-connection behavior.

- **AVEVA AF Proxy - Request and Result Caps Removed:**  
  The proxy now serves whatever the client requests, including Visual KPI current-value requests with 2500 lookups.

- **AVEVA AF Proxy - Large Current-Value Loads:**  
  Large current-value loads are no longer abandoned mid-flight. Bulk SDK time budgets now scale with item count.

- **AVEVA AF Proxy - Point Type Preloading:**  
  AVEVA PI point types are bulk-preloaded once per batch instead of requiring one round-trip per point, significantly improving performance for large current-value requests.

- **AVEVA AF Proxy - x64 Service:**  
  The service now runs as x64.

- **AVEVA AF Proxy - Per-Phase Timing:**  
  When `log_data_retrieval` is enabled, the proxy logs per-phase timing for resolve, bulk read, point-type preload, and conversion.

### Fixes

- **tModel RCS:**  
  Fixed attributes resolved through an interface or formula displaying the raw lookup instead of the resolved value, which caused object names to appear as tags or expressions such as `PLANT.PUMP1.NAME`.

- **tModel RCS:**  
  Fixed chart pens and slices that share a display name all receiving the same value in Path mode.

- **tModel RCS:**  
  Fixed Boolean tModel flags failing to save due to a tinyint conversion error.

- **tModel RCS:**  
  Fixed chart colors from tModel rendering black until hovered.

- **tModel RCS:**  
  Fixed the box plot upper control limit incorrectly duplicating the lower control limit.

- **tModel RCS:**  
  Fixed data errors during large cache runs re-inserting already committed objects and causing a primary key violation that hid the original error. Only the failing batch is now retried or bisected, and the offending object is logged and skipped.

- **AVEVA AF Proxy:**  
  Fixed requests that arrived while a connection was being established receiving an immediate 503 instead of waiting for the connection, particularly at service startup and after reconnects.

- **AVEVA AF Proxy:**  
  Fixed AVEVA PI Data Archive timeout settings not taking effect on already-connected servers and generating unnecessary warnings.

- **AVEVA AF Proxy:**  
  Fixed transient stalls recycling the process instead of clearing normally. Retired connection pipes are now disposed correctly.

- **AVEVA AF Proxy:**  
  Request validation failures now correctly return HTTP 400.

- **AVEVA AF Proxy:**  
  Defaulted and adjusted configuration values are now logged as warnings or informational messages instead of errors.

**Compatibility:**  
Tested with inmation version v1.94.3.21651.

</Update>

<Update label="July 16, 2024" description="Release Notes for Build 5.100.52.648">

This release adds aggregate and omit syntax for AVEVA PI and AF lookups, aggregate-based bar and Pareto charts, and finer cache controls for the AVEVA AF Interface Proxy.

### New Features

- **Aggregate Syntax for AVEVA PI and AF Lookups:**  
  Lookups now support aggregates, for example `sinusoid|avg|7d`. Available aggregates are `avg`, `sum`, `count`, `min`, `max`, `range`, and `stddev`.

- **Omit Syntax for AVEVA PI and AF Lookups:**  
  Lookups can now exclude specific values, or values above or below a threshold. For example, `sinusoid|omit|min=50,max=100` only shows values between 50 and 100. Use `val` to omit specific values, for example `val=[234,241,250]`. You can combine `min`, `max`, and `val`.

- **Aggregate-Based Bar and Pareto Charts:**  
  Added support for aggregate-based bar charts and Pareto charts.

- **AVEVA AF Interface Proxy - Cache Expiration Controls:**  
  Added finer-grained controls over cache expiration for subscription-based and non-subscription-based values.
